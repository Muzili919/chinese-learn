## 🔥 白屏Bug修复 (commit b58cac3)

**根因**: WordCannonGame.jsx 中 `shieldIndicator` 样式对象在组件函数**外部（模块级）**定义，但引用了组件内部的 `slowMode` useState变量 → **ReferenceError: slowMode is not defined** → React崩溃→白屏

**具体错误链**:
1. `const shieldIndicator = { top: slowMode ? 72 : 46, ... }` — 模块级作用域，slowMode不存在
2. `const styles = {...}` 对象缺失（未定义），导致 `styles.shieldIndicator` 也是undefined
3. 渲染 `<div style={styles.shieldIndicator}>` 时崩溃

**修复方案（3处改动）**:
1. `shieldIndicator` 改为函数: `const getShieldIndicator = (slowMode) => ({...})`
2. 引用处改为: `<div style={getShieldIndicator(slowMode)}>`
3. 新增 `const styles = {...}` 收集所有样式常量

**附加修复**:
- MV1Demo.jsx: 云端加载失败时fallback到initialState + 无用户(god模式)直接用initialState
- App.jsx: MV1Demo传入grade prop
- SelfTestPage.jsx: 语文system prompt微调

**排查方法**: 用playwright-cli打开页面捕获控制台日志，精确定位到 `ReferenceError: slowMode is not defined`

## 🐛 5个宠物系统Bug修复 (2026-04-16晚)

### Fix #1: 动作切换点击无效 ✅
**根因**: `resolveEmotion(pose, stats)` 中，用户点击切换来的 pose（happy/excited/wave等）被四维属性判断覆盖 → 多个不同pose解析为同一emotionKey → 看起来切换没反应
**修复**: Pet.jsx 重写 `resolveEmotion()` — 新增 `USER_CYCLING_POSES` 白名单，显式动作直接透传不走状态判断。优先级：P0显式动作 > P1系统锁定 > P2四维状态

### Fix #2: 宠物自动多小鱼干 ✅
**排查结果**: 无"自动购买"代码。鱼干增多原因：上帝模式初始99条 + 每日任务奖励发放basic/advanced鱼干（daily_learn→+1snack, daily_streak→+1rare_snack）。非bug，是设计行为

### Fix #3: 游戏不扣经验 ✅
**设计确认**: 游戏用每日次数限制(dailyAttempts)而非经验消耗，设计如此
**附加修复**: 添加了3秒定时刷新storage XP的useEffect（Fix #5联动），确保从游戏切回时经验值正确

### Fix #4: 抽卡券经验够但买不了 ✅  
**根因**: `handleShopAction('card_draw')` 走的是"使用已有卡券"逻辑（检查 `cards < 1` 就return），不是"购买新卡券"逻辑！商店点购买永远买不进背包
**修复**: 
- 商店`handleShopAction('card_draw')` → 改为购买逻辑：花500可支配经验 +1张卡券到背包
- 背包`handleUseItem('card_draw')` → 改为使用逻辑：消耗1张卡券触发drawCard抽卡
- 形成 **购买(商店) → 使用(背包)** 的正确闭环

### Fix #5: 学习后宠物得不到成长经验 ✅
**根因**: `totalXP` 在MV1Demo中只在初始化时读取storage一次，答题后storage.addXP更新了但宠物页不知道
**修复**: 
1. 新增3秒定时sync useEffect：每3秒对比storage.getXP与state.exp，不一致则刷新
2. `totalXP` 改为useMemo（依赖state.exp变化），确保渲染用最新值

## Fix #5 增强版: 宠物经验同步终极修复 (commit 0e5aa48)
用户反馈学习后宠物经验仍不动，深入排查发现3层叠加问题:
1. MV1Demo卸载→重挂载，useState初始值用gameState(过时)
2. 初始化useEffect异步(fetchMV1State)，回来前UI显示旧值
3. totalXP的useMemo依赖数组缓存，React跳过时不重算

修复方案(三层防御+totalXP重构):
- L1: 3秒定时轮询(持续对比storage与state.exp)
- L2: visibilitychange立即刷新(从答题页切回时触发)
- L3: 挂载后500ms兜底(不等定时器)
- totalXP改useRef+每渲染读storage，彻底绕过useMemo
